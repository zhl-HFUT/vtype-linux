# 剪贴板互通

与已关联的手机或 Mac 双向交换新复制的纯文本，可再单独开启 PNG/JPEG 图片。默认关闭，需要单独启用；启用云候选、词库同步或常用语不会打开剪贴板。

## 启用和关闭

先按[安装与使用](安装与使用.md#2-关联手机或电脑可选)关联设备，并在官方客户端开启跨设备复制粘贴。在 Linux 图形桌面的终端安装对应工具：

```sh
sudo apt install xclip          # X11，或 GNOME Wayland 的 XWayland 后端
sudo apt install wl-clipboard   # 支持 wlr 数据控制协议的 Wayland 桌面，如 Sway
```

然后执行：

```sh
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard enable
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard status
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard disable
```

启用期间，之后新复制的纯文本会发给微信输入法服务器，包括从其他应用复制的文本。手机或 Mac 的新文本会写进 Linux 系统剪贴板，可在应用中正常粘贴。默认不同步图片；文件以及超过 256 KiB 的文本不会发送；手机或 Mac 发来的长文本最多接收 1 MiB。

要同时同步图片，启用时加 `--images`（不加则关闭图片同步）。X11 / XWayland 上图片的读写还需要 GTK 3 的 Python 绑定：

```sh
sudo apt install python3-gi gir1.2-gtk-3.0   # 仅 X11 / XWayland 同步图片需要
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard enable --images
```

开启后，之后新复制的 PNG/JPEG 图片（包括截图）会加密上传到腾讯云 COS 并发给同组设备，手机或 Mac 复制的图片会写进 Linux 剪贴板。`clipboard status` 的 `images` 显示是否开启。

后台进程使用 `wetype-clipboard.service`，登录桌面后自动启动。不需要修改或重启 Fcitx5。默认 `auto` 先检查 Wayland 桌面的后台剪贴板协议：支持时使用 wl-clipboard，否则使用 X11 / XWayland 的 xclip。探测只读取协议注册表，不读取文字、不创建窗口。`enable --backend x11` 或 `enable --backend wayland` 可以指定后端；指定 Wayland 时也会检查后台协议，不使用会弹出临时窗口的读取方式。

GNOME Wayland 通常需要安装 `xclip`，并保留桌面的 XWayland 支持。旧配置已经指定 `wayland` 时，安装新版后执行下面命令改用自动选择：

```sh
python3 ~/.local/lib/wetype-ime/arm64/wetype-cloud.py clipboard enable --backend auto
```

`clipboard disable` 只关闭剪贴板同步，保留设备身份及云输入功能。顶层 `disable` 同时关闭云功能和剪贴板同步。用户安装的卸载流程也会停止它创建的剪贴板服务。

## 同步规则

- 每次启动以当前 Linux 剪贴板为基线，不上传启动前已有文字；只发送进程启动后检测到的新文本变化。
- 本地文本变化约每秒检查一次，远端最新消息每 5 秒查询一次。网络或身份锁出错时逐步退避，最长 60 秒；不保存待上传文本正文。
- 只在读取设备身份的瞬间持有身份锁，网络请求不占锁，不影响打字时的云候选。启用了五分钟刷新任务（`enable --timer`）时由它续期登录；否则身份超过 10 分钟未更新，同步进程自己续期。
- 超过 256 KiB 的远端文本由官方放在腾讯云 COS，Linux 只从 `*.myqcloud.com` 的 HTTPS 地址下载，最多 1 MiB；下载失败不推进游标，下一轮重试。无法按 UTF-8 解码的远端内容直接忽略。
- KDE 的 Klipper 在剪贴板变空（例如同步进程重启）后放回的历史内容带有 `application/x-kde-onlyReplaceEmpty` 标记，不当作新复制，不发送。
- 只操作系统 CLIPBOARD，不操作 X11 的 PRIMARY 选区。文本保持 UTF-8 和原有换行，单条上限按 UTF-8 字节数计算。
- 只接收同组其他设备的较新、未过期的文本。过期时间以服务器返回值为准；官方服务保存的是最新值，这不是剪贴板历史记录。
- 同一轮发生本地复制时，本地新复制优先。写入远端文本前再次核对当前剪贴板，检测到本地变化就留到后续处理。设备组变化时丢弃旧组尚未发送的内容。
- 接收后不回传；系统写入或游标保存失败，不推进接收游标。发送结果不明时等待远端核对，不自动重发；`status` 的 `send_unknown` 表示尚未确认。
- 关闭或重启期间错过的本地复制不会补传。仍有效的远端新消息可以在恢复运行后接收。

## 图片

- 只同步 PNG 和 JPEG。复制时系统剪贴板同时提供文件路径（`text/uri-list`，如在文件管理器里复制图片文件）的按文件处理，不发送；GIF、WebP 等其他格式不发送。
- 发送单张最多 10 MiB（官方服务器的上传上限），接收最多 16 MiB。图片以随机密钥 AES-128-CTR 加密后上传，消息里只有下载地址、原图 MD5 和密钥；接收时只从 `*.myqcloud.com` 下载，解密后核对 MD5 和格式。
- 收到的图片按原格式写入剪贴板（`image/png` 或 `image/jpeg`）。X11 / XWayland 上收到的 JPEG（如手机相册原图）同时以 PNG 提供，只认 PNG 的应用也能粘贴；PNG 在第一次粘贴时才转换，按照片方向摆正，长边超过 2560 像素时等比缩小（照片转成无损 PNG 原尺寸可达几十 MB），需要原图的应用仍可取 JPEG。Wayland 上只提供原格式，只认 PNG 的应用遇到 JPEG 时贴不出来。
- iPhone 上的微信输入法只在键盘弹出时读取剪贴板；在相册等应用里复制图片后，弹出一次微信输入法键盘才会发出。
- 来源应用每次被读取都要重新提供图片数据，为此图片在剪贴板类型不变时最多每 5 秒重读一次；在同一个应用里连续复制两张图，第二张最多晚 5 秒发出。
- X11 上本机写入的图片由一个后台 GTK 进程提供给粘贴的应用，下一次复制取代它时自行退出。
- 图片同样不保存在状态文件里，游标和统计与文本共用。

## 状态和兼容性

`status` 显示 `enabled`、`running`、`sent`、`received` 和最近错误类别，不输出文本。身份目录中的剪贴板状态文件只保存游标、发送标识、文本指纹和统计，权限为 `0600`；不保存正文，也不把响应写入诊断文件。

服务日志逐条记录本机复制、发送、收到和跳过的消息，只含版本号、类型、大小、耗时、剩余有效期和跳过原因（如“已过期”“来自本机”），不含内容：

```sh
journalctl --user -u wetype-clipboard.service -f
```

X11 / XWayland 的文本使用 xclip，图片使用 GTK 3（xclip 0.13 在 KDE 等带剪贴板管理器的桌面上读写约 1 MiB 以上的图片会截断或丢失）。Wayland 使用 wl-copy/wl-paste，当前要求桌面提供 `zwlr_data_control_manager_v1`（wl-clipboard 2.x 支持的后台数据控制协议）。

| 环境 | 结果 |
|---|---|
| Ubuntu 22.04 x86_64，KDE Plasma X11，与 iPhone 官方客户端 | 实机双向互通 |
| Ubuntu 24.04，隔离 Xvfb 和 Sway 1.9 | 双向 UTF-8、换行、首启基线、防回传、文件过滤和 PNG/JPEG 图片读写（CI 每次检查） |
| Ubuntu 26.04，GNOME Wayland + XWayland | 自动回退 xclip、后台读取及无临时窗口通过；双向同步规则另在隔离 Xvfb 验证 |

不支持后台协议且没有 XWayland 的桌面无法启用同步，会提示原因。缺少工具时按提示安装 `xclip` 或 `wl-clipboard`。仅提供新版 `ext_data_control_manager_v1` 的桌面也先使用 XWayland 后端，避免旧版 wl-clipboard 弹窗。

iPhone 端由微信输入法在使用中收发；迟迟收不到时，弹出一次键盘或打开微信输入法 App。报文依据 [wx-ime-sdk 固定版本](https://github.com/mkdir700/wx-ime-sdk/tree/1ec70393cc9524c6c341cf768f090b0176586f72)核对，该项目不是腾讯官方 SDK。KDE 锁屏时会接管剪贴板并清空内容，这时不会发送任何文本。

排错时先确认在图形桌面执行了 `enable`，再看 `clipboard status`。`refresh_error` 表示身份续期失败，`error` 表示桌面、网络或身份锁操作失败。需要前台观察进程时，先运行 `systemctl --user stop wetype-clipboard.service`，再执行 `wetype-cloud.py clipboard run`；它仍需已经启用的配置。

## 离线检查

```sh
python3 -m unittest discover -s tests -p 'test_clipboard_*.py'
python3 scripts/test_clipboard_desktop.py --backend x11      # 需要 Xvfb、xclip、python3-gi 和 GTK 3
python3 scripts/test_clipboard_desktop.py --backend wayland  # 需要 Sway、wl-clipboard，使用隔离会话
```

这些检查只使用合成文本、合成图片和离线设备组，不需要账号，也不访问官方服务器。
